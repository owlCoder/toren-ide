## Toren IDE 1.0.0-preview.2

An early public Preview for **Windows x64 and Linux x64**. It replaces the unpublished 1.0.0-preview.1 candidate and adds the workspace-loading and C# analysis work described below.

### Before you install

This Preview was published by maintainer decision ahead of the full release checklist:

- **macOS is not included.** The macOS bundles are not Developer ID signed or notarized, so they are not offered as public downloads.
- **No Release Validation record exists for these archives.** They were not published through the guarded `Publish Release` workflow, and hands-on smoke, accessibility and performance checks of these exact archives on Windows and Linux have not been recorded.
- **The Windows archive is not Authenticode signed.** Windows SmartScreen may warn when `Toren.App.exe` is first started.

Treat it as a build for early adopters, and report problems with the OS, Toren version, workspace type and steps to reproduce.

### Included packages

| Platform | Archive | Start |
| --- | --- | --- |
| Windows x64 | `Toren-IDE-win-x64.zip` | Extract all files, then run `Toren.App.exe` |
| Linux x64 | `Toren-IDE-linux-x64.tar.gz` | Extract all files, then run `./Toren.App` |

Each archive includes the .NET 10 runtime, Toren's application icon, license, launch instructions and `release-info.json` with its version, architecture and source commit. A separate .NET runtime installation is not needed to launch Toren. Install the SDK required by your projects for restore/build/run; Git is required for source-control features. Linux desktop/native dependencies still apply.

A SHA-256 file accompanies each archive. Verify a download with `sha256sum -c Toren-IDE-linux-x64.tar.gz.sha256` on Linux or `Get-FileHash Toren-IDE-win-x64.zip -Algorithm SHA256` on Windows.

### Changes since the preview.1 candidate

- **Opening large solutions.** All tools now share one evaluated project snapshot per workspace, evaluated in a single MSBuild invocation per stage and reused while the project files are unchanged. On the 220-project Orchard Core solution the startup-project selector is populated after about 2 seconds instead of 345, and the first workspace diagnostics appear after about 12 seconds instead of 527.
- **C# diagnostics while editing.** Diagnostics for the active document analyze that document instead of its whole project, and parsed sources and source-generator state are reused between requests. In a 154-file project one pass takes about 0.8 seconds instead of 2.8.
- **Responsiveness.** Large Explorer nodes are filled in steps, which removes a UI stall of about one second when a 220-project solution opens. The workspace file index, text search and the Problems scope index are faster.
- **SDK selection.** Project evaluation now runs with the SDK selected by the workspace's `global.json`, as building does.
- **Packages.** Installed packages are queried when the Packages dialog is first opened instead of on every workspace open.

The figures come from service and headless application measurements on one macOS machine; Windows and Linux performance was not measured. Method, raw values and limits are in `docs/design/performance-review.md`.

### Also in this Preview

- Refined dark/light palettes, rounded controls, aligned dialogs and responsive tool panels.
- Settings and NuGet Packages in dedicated dialogs; Source Control, Debug, HTTP and other tools in the sidebar.
- Build, Rebuild and Clean controls, build activity feedback, diagnostic navigation and Problems.
- An integrated terminal that starts when its tab opens and can stop its process.
- C# navigation/completion, test workflows, Git, ASP.NET Core, HTTP, EF Core and Docker Compose tools.

### Known limitations

- Some capabilities remain partial; `docs/progress.md` tracks their exact scope.
- Adding or removing a file, or editing a project file, re-evaluates all projects of the workspace in the background.
- Rendering and input latency in a native window were not re-measured after the performance work.
- No installer or automatic updater is included.
